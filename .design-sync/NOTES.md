# design-sync notes — jobcut Design System

Re-adopted the existing claude.ai/design project "jobcut Design System" (its UUID is
pinned in the local, gitignored `.design-sync/config.json` — copy it from
`config.example.json` and add your own `projectId`). The prior sync's config/previews
were never committed to this repo, so this run reconstructed them from scratch. Source
of truth: the current `web/` console code (Next.js 16, App Router, Tailwind v4).

## Shape & entry (package shape, synth-from-source — no dist)

- `web/` is a Next.js **app**, not a packaged library — there is no `dist/`. The bundle
  is built from source via an explicit **barrel entry** `web/.design-sync/entry.tsx`
  (passed with `--entry`), which re-exports the 17 scoped components (default exports
  renamed — a synth `export *` entry would silently drop them).
- Run from repo root:
  ```
  bash web/.design-sync/build-css.sh   # cfg.buildCmd — regenerates compiled.css
  node .ds-sync/package-build.mjs --config .design-sync/config.json \
    --node-modules web/node_modules --entry web/.design-sync/entry.tsx --out ./ds-bundle
  node .ds-sync/package-validate.mjs ./ds-bundle
  ```
- `pkg` is `"web"` (generic name) so `globalName` is pinned explicitly → `window.JobcutDs`.
- Scope = 17 components. **Excluded** (parity with prior sync): `DocumentViewer` and
  `ThemeToggle`/`ThemeSegmented` (app chrome, not design-system primitives).

## next/* + process (why the stubs exist)

- Components import `next/link` and `next/navigation` (`Nav`, `JobCard`), which need the
  Next app-router at runtime and throw standalone. `web/.design-sync/tsconfig.json`
  (via `cfg.tsconfig`) aliases both to render-safe stubs in `web/.design-sync/stubs/`.
  **The tsconfig must be plain JSON with no `//` comment keys** — the converter's
  comment-stripping regex corrupts a `"//"` key and silently disables the alias plugin
  (then real Next gets bundled: 385KB, `process is not defined`, 0 exports on the global).
- `web/.design-sync/shim.ts` (imported first in the barrel) defines `globalThis.process`
  because `lib/api.ts` reads `process.env.NEXT_PUBLIC_API_BASE` (guarded, inside a fn).

## Tailwind v4 CSS + fonts

- `cfg.cssEntry` points at the **compiled** stylesheet `web/.design-sync/compiled.css`
  (gitignored, regenerated by `build-css.sh`). The raw `app/globals.css` (`@import
  "tailwindcss"`) can't be shipped — the utility classes only exist after Tailwind runs.
- Inter is loaded by `next/font` at runtime (`--font-inter`), so standalone it's
  undefined. `build-css.sh` appends `--font-inter` + the metric-adjusted "Inter Fallback"
  face. The 7 Inter subset woff2 are copied to stable names under
  `web/.design-sync/fonts/` with a committed `fonts.css` (`cfg.extraFonts`) — reproducible
  and independent of the per-build `.next` hashes.

## Known render warns (triaged — not new on re-sync)

- `[RENDER_THIN] Spinner` — a bare spinner SVG has no text; renders correctly at 3 sizes.
- `[GRID_OVERFLOW] JobCard` — full-width card; handled with `cfg.overrides.JobCard.cardMode = "column"`.
- `[TOKENS] 1 missing` — `--color-accent-green`: Tailwind emits a `.text-accent-green`
  utility from usage elsewhere in `web/` (not in the 17), but the theme defines
  `--color-green`, not `--color-accent-green`. Below threshold, pre-existing in the app,
  not shipped by any synced component. Left as-is (would be an app-side globals.css fix).
- InfoDot's tooltip is hover-only → invisible in static capture, by design.

## Re-sync risks (what can silently go stale)

- **Preview realism data is inlined** in `.design-sync/previews/*.tsx` (job titles,
  companies, scores). Harmless, but if a component's props change, update the preview.
- **next/* stubs** track only the API surface the components use (`usePathname`,
  `useRouter`, `default` Link). If a synced component starts using another `next/navigation`
  export, add it to the stub or the bundle breaks.
- **Inter Fallback metrics** (`ascent/descent/size-adjust`) were captured from the current
  next/font build; only matters for layout-shift fidelity, not correctness.
- If `web/` adds/removes a component, update **both** `componentSrcMap` and the barrel
  `entry.tsx` (they must agree), then author a preview or it ships the floor card.
- Grades live in gitignored `.design-sync/.cache/`; cross-machine carry-forward comes from
  the uploaded `_ds_sync.json`. A fresh clone re-verifies everything (expected).
